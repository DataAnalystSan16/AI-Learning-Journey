# Day 12 – AI-Assisted Retail Store Performance & Sales Intelligence Project

## Project Overview

As part of my AI Learning Journey, I worked on an AI-assisted Retail Store Performance & Sales Intelligence project using MySQL.

The project simulates a retail business operating across Bengaluru, Chennai and Hyderabad.

I used AI as a learning assistant to understand business requirements, plan the database structure, explore SQL concepts and understand how relational database design supports real-world business analysis.

## AI-Assisted Learning Approach

With AI assistance, I worked through the following activities:

- Converted retail business requirements into database design requirements.
- Planned a relational database schema with nine interconnected tables.
- Understood the purpose of each table, column and relationship.
- Explored appropriate SQL data types and constraints.
- Discussed business scenarios involving orders, partial returns, refunds and monthly targets.
- Understood how database information supports business KPIs and reporting.

## MySQL Hands-on Implementation

Created the `retail_sales_intelligence` database and implemented nine tables:

1. Stores
2. Customers
3. Categories
4. Products
5. Orders
6. Order Items
7. Sales Returns
8. Sales Return Items
9. Store Monthly Targets

### SQL Concepts Practised

- CREATE DATABASE and USE
- CREATE TABLE and INSERT INTO
- PRIMARY KEY and FOREIGN KEY
- AUTO_INCREMENT
- NOT NULL and DEFAULT
- UNIQUE and Composite UNIQUE Constraints
- INT, BIGINT, VARCHAR, DECIMAL, DATE and DATETIME
- DESCRIBE, SELECT and SHOW TABLES

### Hands-on Results

- Successfully created all nine tables.
- Inserted sample records into each table.
- Verified all nine table structures.
- Verified a total of 69 sample records.

## Business Understanding

Explored how the database can support:

- Total sales and order analysis.
- Product and category performance.
- Discounts and product profitability.
- Customer returns and refund tracking.
- Store-wise monthly target achievement.
- Return reason analysis and root cause investigation.

## Important Learning Takeaways

- Why transactional information should be separated into related tables.
- How Primary Keys and Foreign Keys establish relationships.
- Why historical selling prices and costs should be preserved.
- How partial returns should be tracked against original order items.
- Why business rules such as return quantity validation need additional logic.
- How Composite UNIQUE Constraints prevent duplicate store-month target records.

## Project Workflow

Business Requirements → AI-Assisted Database Planning → MySQL Database Design → Hands-on SQL Implementation → Sample Data Insertion → Data Verification → SQL Business Analysis → Power BI Dashboard.

## Key Learning Reflection

This project helped me understand that AI is not just a tool for generating SQL queries. It can also act as a learning partner to explain technical concepts, challenge my understanding through business scenarios and help connect database design with actual business requirements.

I focused on understanding the reasoning behind each design decision rather than simply copying and executing SQL statements.
